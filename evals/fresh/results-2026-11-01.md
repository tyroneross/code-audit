# Fresh-case benchmark results (2026-11-01)

The adaptive methods did not detect more defects than any comparison arm. On 54 fresh defects, `adaptive`, `none+tools`, `bundle+tools` and `fixed-plan` each detected the same 19 cases, case for case. `principles+tools` detected 18. Every pre-registered comparison is **parity**: adjusted p = 1.0 and 0–1 discordant cases. Tools did not help either: `none+tools` detected 19 against 22 for the tool-less `none`, at 17× the tokens. The instrument itself works: the positive control separated at p = 8.0e-7.

Protocol: [README.md](README.md) and Addenda 1–3, committed before the trials or outputs they govern. Raw trials, judge packets, judgments and aggregates are in `.build-loop/evals/fresh-r1*`, `fresh-r2*` and `fresh-stats-*.json` (untracked).

## Instrument validity

- **Positive control.** `hint` detected 46/54 and `none` 22/54: 25 vs 1 discordant cases, exact McNemar p = 8.0e-7. The instrument detects a large planted effect.
- **Discrimination.** `none` at 0.41 and `none+tools` at 0.35 are both below the 0.75 ceiling, so the case set is not saturated.
- **Judging.** 20 Opus-tier judges graded 124 blinded packets holding 1,075 findings, and every finding got a row. Spot checks of 8 random decisions agreed with the oracle on 7. One accept was lenient: a bare-`500` match was counted as the oracle's inline-CSS mechanism. Each case's packet held every arm's findings, so one judge's leniency applied to all arms alike.
- **Manipulation check.** It took. `adaptive` and `fixed-plan` ran `scan.py` and `recon.py` in 62/62 trials. `none+tools` ran `scan.py` in 19/62 and `recon.py` in 32/62. `bundle+tools` ran `scan.py` in 18/62. The methods changed what the agents ran, not what they found.
- **Case determinism.** Detection is fixed per case, as the 2026-11-01 RCA found on the old set. The tool arms differ by at most 1 case.

**Sensitivity analysis: network-flagged trials.** The `evals/hard` network audit flagged 33 tool-arm trials, spread across all five arms (4–8 each).
- **Inspection.** Every flagged command was a probe in which a model ran the repository's own command classifier or hook on test strings, for example `'git push'`, `npm install lodash --before=…` and `https://example.test`. None ran a network tool or opened a connection.
- **Primary.** The pre-registered rule invalidates all 33, so the primary analysis drops them pair by pair.
- **Sensitivity.** Re-admitting them changes no verdict.
- **Bias against probing.** The audit penalizes probing, which `adaptive` asks for. That is a bias against the arm under test, and it did not decide the outcome.

## What this does and does not show

- **Shows.** At medium effort, with tools and a whole repository, `gpt-6.1-sol` detected the same defects with and without code-audit's methods, its bundle, or the source plugin's bundle. Tools alone did not raise detection over the tool-less packet, and cost about 17× the tokens and 2.6× the time. A second review pass added 2 cases (p = 0.5).
- **Does not show.**
  - **Effects on other models or higher effort.** Claude-hosted reviewer arms were blocked: no API key exists.
  - **Fan-out and lane designs.** Every arm was a single agent.
  - **Defects outside the oracle.** Detection credits only the mined defect. Arms that found other real defects get no credit, and finding counts differ: `adaptive` reported 183 findings against 209 for `none+tools`.
  - **Effects smaller than about 6 net discordant cases in 54.**
- **Interpretation** [INFERRED]. For this model and these cases, detection depends on the case, not on the procedure. A case the model "sees" is found by every arm; a case it does not see is found by none. The levers left untested here are model, effort, multi-pass or parallel review at larger scale, and per-case facts such as a class hint. The hint moved detection by 0.44.

## Disclosures

- **Labels seen.** The orchestrator saw each case's key and one-line class label before the methods were frozen. One mining lane's labels described part of each mechanism. The methods text predates the cases, and its authoring lane did not read them.
- **Harness reruns.** 15 tool-arm trials on F42–F44 failed before the model ran, because an absolute symlink in the decision-doctor archive stopped extraction. They were rerun once after the fix in 3a63677. 7 of the 15 reruns were then network-flagged.
- **Tool sources.** Two runner processes served round 2. The first copied tools from the worktree, which was clean at de06478 for the whole run. The second wrote them from git at de06478 and recorded their hashes.
- **Single run.** One repetition per case, one judge per packet.
