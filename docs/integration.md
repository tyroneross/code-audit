# Integration

This repository is the combined product source. The original repositories, installations and skill symlinks remain intact.

Audit scripts/cards are imported under `skills/`; debugger source and compiled code under `runtime/debugger`. The private runtime package removes its automatic postinstall setup. The root launcher starts only local MCP, with existing tool schemas and compatible storage paths. No lifecycle hooks are included.

The public router and debug adapter connect the workflows. Legacy instructions now disclose absent memory and independent execution; KNOWN_FIX still requires current-context validation. Shared engineering references live under `skills/code-principles/references/`. The runtime's internal server name/version identify the imported debugger; the root plugin version identifies the combined product.

The legacy CLI is retained for source/build compatibility, not registered as a plugin command. Procedures work without Claude-only agent registration. Since 2026-10-28 the seven coding-debugger agents ship in `agents/` for Claude Code (adapted: no npx memory call, caller-supplied incident candidates, fix-critique pinned to opus); hosts without agent registration still follow the same skill procedures. Debugger commands and the Stop mining hook are recorded as removed imports in [source provenance](source-provenance.json). Earlier synthetic prose/pseudocode comparisons found no reliable winner: pseudocode-first is a navigation choice, not a proven accuracy gain. Details load conditionally.

The memory entrypoint was rewritten to match actual MCP schemas: manual isolated JSON writes and assumed domain-agent registration were removed. Structured verification metadata remains conservative; check receipts belong in the incident narrative and linked report. Audit package tests now validate the combined plugin identity/version separately from the retained audit-tool version.

Independent Opus review exposed inherited runtime issues. The combined runtime now disables internal file logging by default, describes retrieved fixes as historical candidates, bounds project log reads, recovers from malformed stdio lines, answers ping and negotiates supported basic-tool protocol versions. Outcome records reject unknown incidents, omit unknown historical verdicts and declare their append side effect. Unused legacy memory references and incidental session state were removed. These changes apply only to this combined repo.

The review-feedback update adds shared review and incident-learning references through the existing router, focused review, debug, memory and specialist-review paths. It keeps severity separate from origin, uses causal identity and evidence-sensitive reopening, and preserves changed-plus-affected-path coverage. Budgets are intentional and shared with the existing debug-loop limit. The reviewer evaluation scores externally adjudicated saved outputs; it does not authenticate receipts, grant approvals, change MCP schemas or claim memory improved task outcomes. Legacy incident narratives carry negative attempts and applicability; lifecycle changes are not an invented MCP capability.

## Installed host scope — 0.3.0

Portable `mcp.json` resolves the launcher with `${PLUGIN_ROOT}`; Claude's `.mcp.json` retains `${CLAUDE_PLUGIN_ROOT}`. An actual Codex 0.163.0 isolated install rejected the old portable launcher path at MCP startup; changing the portable variable restored automatic discovery. Its MCP cwd is the installed package, so the memory tools now accept an optional absolute `project_root`. It selects that call's local corpus without changing cwd or shared process state. A package-root host refuses unscoped memory access unless an explicit legacy memory path was configured. Claude 2.1.306 retained project cwd and also completed the explicit-root roundtrip. Log inspection remains within actual server cwd.

Both hosts loaded the combined entry skill and automatically discovered all eight tools; actual status/store/list/search/detail roundtrips were observed in separate synthetic projects. No global installation, default mining or shared memory was enabled. CLI integration is not desktop UI acceptance.

Corpus loaders preserve array return types and add optional bounded per-call inspection counters. Search propagates them, retains usable records and surfaces read/parse/shape skips. Both temporal paths compare timestamps with a timestamp cutoff, including a zero-day preference. Historical verification labels describe records, not current repair proof; default search tiers are not calibrated probabilities.
