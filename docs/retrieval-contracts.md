# Programmatic retrieval contracts

The bundled debugger preserves useful matches and reports incomplete reads across raw, tiered, quick and progressive retrieval. Historical records remain leads; their rank, diagnosis metadata and recorded success rates are not calibrated confidence in a current repair.

`checkMemory` and `checkMemoryScaled` inspect patterns before incident candidates. Matching patterns take precedence, including queries without keywords when the configured threshold permits a zero score. `max_results` limits the selected collection. Indexed retrieval scans ranked postings until its eligible-candidate allowance is filled or candidates are exhausted; restrictive filters can require more file reads, which remain visible in coverage. `include_unvalidated:false` requires an explicit `quality_gates.guardian_validated:true` on incident matches; an absent gate cannot bypass it. `tags_filter` accepts any listed exact tag, and `agent_filter` requires an exact incident agent or a declared pattern applicability entry.

`checkMemoryTiered` retains its compact and summary fields. A full-tier request returns complete records in additive `full_incidents` and `full_patterns`, keeping compact consumers typed as before. Summary, compact and full tiers use serialized UTF-8 byte-size estimates to select records within their allocated data budgets. `tokens_used` is an estimate with metadata reservation; it is not tokenizer measurement or a guarantee covering arbitrary transport framing. Oversized records are omitted and counted in truncation metadata.

`quickMemoryCheck` counts incident and pattern summaries, honors an explicit zero result limit, and exposes `coverage` and `inconclusive`. Progressive matches expose a separate `retrieval_score`; `confidence` is retained as explicitly labeled historical metadata using `confidence_kind`. Partial NO_MATCH results remain inconclusive. Coverage describes inspected files or indexed candidates; it does not prove that every stored file was inspected.

Stored incident/pattern IDs must match their declared formats before writes. Corpus readers reject mismatched filenames and malformed consumed fields while preserving supported legacy omissions. Dictionary keys such as `constructor` and `__proto__` remain ordinary data across index serialization. Archival refreshes active keyword postings. `searchIncidentLog(query, config, coverage)` retains usable log matches and optionally reports per-record skips; callers should pass a coverage object when distinguishing empty and incomplete reads matters.
